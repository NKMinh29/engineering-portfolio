# 08. Frontend web và truy cập được

**Nhóm:** Phần mềm & dữ liệu · **Mục tiêu:** nắm nền tảng, tự làm một demo nhỏ và giải thích giới hạn của nó.

## Học những gì?

1. HTML ngữ nghĩa.
2. CSS layout responsive.
3. JavaScript và DOM.
4. Event và state.
5. Fetch API.
6. Biểu đồ và bảng dữ liệu.
7. Form validation.
8. Accessibility bàn phím.
9. Performance và test giao diện.

## Giảng nhanh

HTML diễn tả cấu trúc; CSS kiểm soát hình thức; JavaScript cập nhật trạng thái. Dùng thẻ `button` thật giúp người dùng bàn phím và trình đọc màn hình tương tác dễ hơn một `div` có sự kiện click. Dashboard cần hiển thị đơn vị dữ liệu và tình trạng kết nối.

## Bài tập ngắn

1. Viết form sensor ID có thông báo lỗi dưới trường nhập.
2. Dùng bàn phím đi qua tất cả nút không cần chuột.

## Project portfolio: Dashboard vận hành robot giả lập

**Các bước thực hiện:**

1. Tạo giao diện HTML CSS gồm pin trạng thái tốc độ cảnh báo.
2. Kết nối API file JSON mẫu hoặc API ở chuyên đề 07.
3. Hiển thị dữ liệu thiếu và stale bằng trạng thái riêng.
4. Thêm lọc thời gian và responsive màn hình điện thoại.
5. Chụp màn hình ít nhất ba trạng thái và thử điều hướng bằng bàn phím.

**Kiểm tra kết quả:**

- Dữ liệu có đơn vị và thời gian cập nhật.
- Màn hình nhỏ không che mất cảnh báo quan trọng.

**Đưa lên GitHub:** tạo repo riêng gồm `README.md` (bài toán, kiến trúc, cách chạy, kết quả đo, giới hạn), mã nguồn hoặc file thiết kế, dữ liệu mẫu nhỏ/nguồn dữ liệu, ảnh chụp hoặc GIF demo, và giấy phép cho những tài sản được phép chia sẻ. Ghi rõ điều kiện chạy và commit theo các mốc thiết kế → demo → kiểm chứng. Tránh tải lên khóa API, dữ liệu riêng tư hoặc bộ dữ liệu lớn.

**Điều kiện thực hành:** Trình duyệt và editor có sẵn; dùng JSON tĩnh để bắt đầu

Bạn giải thích được đầu vào/đầu ra của demo, tự chạy lại từ README, cho thấy ít nhất một trường hợp thành công và một trường hợp lỗi hoặc giới hạn. Phần học sâu cần thêm thời gian: dùng nguồn trên để mở rộng sau khi bản cơ bản đã chạy.
